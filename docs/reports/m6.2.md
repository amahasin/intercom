# M6.2: feedback round

Twelve changes from using M6.1. Not a plan milestone; the version is still 0.6.0 (no bump, no installer built, nothing committed).

## What changed

| #   | Request                                                            | Result                                                                                                                                                      |
| --- | ------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Rename to InterCom                                                 | Every name a person sees. Wire and storage identifiers are unchanged on purpose (see decisions). Data folder, firewall rules and installer names carry over |
| 2   | New icon, a message bubble, everywhere                             | One shape drawn by `gen-icon.mjs` (PNG, ICO) and `Logo.tsx`: window, taskbar, tray, toasts, installer, title bar, ring window                               |
| 3   | Toasts show the app name                                           | The user model id now matches the installer shortcut; a development run gets its own shortcut. The old id matched nothing                                   |
| 4   | Independent windows for calls and meetings                         | One window per call, running that call's media. The main window stays free and shows a call bar                                                             |
| 5   | Small incoming-call card, bottom right, always on top, independent | Frameless card above all windows, shown without taking focus; for a waiting call it offers the options                                                      |
| 6   | No system notification for incoming calls                          | Removed. Missed calls still leave a toast and an Activity entry                                                                                             |
| 7   | Main window like Teams                                             | Filter chips, Favorites and Chats sections that fold, row menu (favorite, unread, mute, hide), Chat and Shared tabs, back and forward arrows                |
| 8   | Reactions outside the bubble                                       | Under it, with a hover card of who reacted                                                                                                                  |
| 9   | Call canvas follows the light theme                                | Theme tokens instead of a fixed dark canvas                                                                                                                 |
| 10  | Controls hidden behind tiles when maximised                        | Grid rows are sized by the window; the body clips; the control bar cannot be covered                                                                        |
| 11  | A call arriving during a call                                      | Waiting call with Hold and accept, End and accept, Add to current call, Decline; held calls keep running; Resume swaps                                      |
| 12  | Remote control of a shared screen                                  | Request, Allow or Deny, Stop. Mouse, wheel and keyboard drive the shared screen                                                                             |

Decisions, with the alternatives turned down, are in `docs/decisions.md` ("M6.2").

## Bugs found while testing

- **A screen share in an audio-only call never showed.** The receiver took the first video line for the camera; an audio call has no camera line, so the share arrived as a "camera". Found because remote control needs a share in a voice call.
- **A call that failed instantly left an empty window.** The core finished the call before the new window had loaded, so the window missed `call.ended`. The core now keeps ended calls for a minute and a new window asks (`calls.ended`).
- **Stale call updates wiped the "ended" message** (fixed earlier in this session, same root cause: updates queued before the end arriving after it).

## Tests

- `npx vitest run`: 158 tests pass (153 before). New: call waiting in the core (waiting, busy for a third, hold and resume, end and accept, decline, add to call, ended-call lookup), the new installer name in the update check.
- `pnpm e2e` (33 tests): the last full run had 30 passing; the three failures were test code that still used the old service name, the old reaction position, and a call window polled before its engine had started. All three pass after the fixes. New: `m62-calls.spec.ts` (call windows; the ring card's position, always-on-top and no toast; maximised controls reachable; call waiting with hold, resume and add; remote control moving a real pointer) and `m62-ui.spec.ts` (name, reactions under the bubble, favourites, filters, row menu, back and forward, Shared tab). The older call specs now drive call windows.
- `pnpm lint`: no errors (two React Compiler warnings about TanStack Virtual). `check:origins`, `check:branding`: clean.

### Known flakes on this PC

- `m4-mesh` (8 people, 1 minute) fails sometimes late in a long run when the machine is busy, and passes alone. Unchanged since M6.1.
- `m6-scale` "outgrows the mesh" failed four times in a row once, also on the untouched M6 tag, and passes otherwise.
- Fuzz tests can fail with `EPERM` on a temp folder right after an e2e run (a process still releasing it); they pass on a rerun.

## Not done, and risks

- **Remote control** needs a real desktop. It cannot control elevated windows, the secure desktop or Ctrl+Alt+Del. Window shares cannot be controlled. Key injection was not exercised in tests (it would type into whatever has focus); only pointer movement was verified on a real screen. Keyboard mapping is by scan code for a US-style key set (about 100 keys).
- **Hold needs direct calls.** Relayed meetings (above the mesh limit) cannot be put on hold.
- **Add to current call** shows the caller "Call declined" and then a call from this PC; they are not auto-joined.
- **Sounds** are checked by their log, not by listening.
- **Teams-style main window:** not done are Open in new window, Move to section, Remove chat history, and the Recap, Notes and Storyline tabs.
- **Installed-build behaviour is not tested here:** toasts naming "InterCom" with the icon, the in-place upgrade from OfficeMesh, and the data-folder move need a packaged build (see `docs/manual-test.md`, "M6.2").
- **24-hour soak: running, not finished.** It was started on 2026-10-06 at 15:45 local through Task Scheduler (task `InterCom-soak-24h`), stopped on purpose at about minute 8 for the M6.3 rebuild, and restarted on the M6.3 build at 16:11 (see `m6.3.md`). The two earlier runs died early (minute 85 and about minute 28), killed from outside by a Ctrl+C or similar that reached their console. Results go to `test-results/soak-24h.json`; this report and `m6.md` need the number added. Until then the M6 done-when (no crash, under 50 MB growth over 24 hours) is not shown.
