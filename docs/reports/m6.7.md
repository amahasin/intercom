## Found while testing

- My PowerPoint reader returned the slide number instead of the slide's relationship id (`<sldId id="256" r:id="rId1">` has two attributes with the same local name), so no slide was found. Fixed; covered by the e2e test.
- pdf.js 6 sizes its invisible text with CSS variables my stylesheet did not use, so search highlights were tiny and misplaced. Fixed (checked in a screenshot).
- The core had no types for `.wav`, `.webm`, `.svg`, `.json`, `.md` and a few others; added (a free-form string on the wire, so older PCs are unaffected).

## Not verified

- Very large PDFs (hundreds of pages) and Office files near the size limits: only small generated files were used. A real, messy Word or Excel file may show things differently (headers, footnotes, merged cells, charts and text boxes are not drawn).
- PowerPoint shows slide text only, by design; pictures and layout are not drawn.
- Old binary formats (.doc, .xls, .ppt) are not read; they open in the PC's own program.
- The viewer in a call window: files there open in the PC's own program.
- Dark mode of the new cards and viewer was not looked at (the pages themselves are white on purpose).
- Nothing was built into an installer or run on a clean machine this round.
