# M6.12 report: a public release, with updates from GitHub

- **Published:** https://github.com/amahasin/intercom (public, MIT), release `v0.14.0` with the x64 and ARM64 installers (not code-signed), `SHA256SUMS.txt` and `Install-InterCom.cmd`. GitHub's digests for the two installers are the SHA-256 values in `SHA256SUMS.txt`.
- **Updates from GitHub:** installed builds ask the GitHub API for the latest release every 6 hours, offer a banner with "Install and restart", download the installer checking size and SHA-256, and run it. The office's shared folder, if set, comes first and stays required; a release can ask for a required update with a line `intercom:required`. Settings > Updates has a switch for it. Only GitHub's hosts are contacted; `check:origins` allows exactly the one address.
- **Tried for real:** `tools/scripts/check-github-update.mjs` against the live release (0.13.0 is offered 0.14.0 with the right asset and digest for each architecture; 0.14.0 is offered nothing), and `tools/scripts/check-github-download.mjs` downloaded the 105 MB installer from github.com (through GitHub's redirect to its storage host) with size and SHA-256 matching.
- **Not tried:** an installed 0.13.0 or older build taking the update (they do not have this code: 0.14.0 is the first that looks at GitHub), the installers themselves, the SmartScreen workaround on another PC.
- **Personal and sensitive information:** the tree (tracked and untracked files) and the whole history were searched for e-mail addresses, user and PC names, private addresses and shares, keys, tokens, certificates and colleagues' names. Removed: the office's share (address and name) from the source and documents (now a build setting, `INTERCOM_OFFICE_UPDATE_FOLDER`, empty in the public build), one colleague's file name in a test, and the author's e-mail address from the 7 old commits (rewritten to the GitHub no-reply address; the original history is in `intercom-history-backup.bundle`, outside the repository, not published). The built installers' text files were scanned too: the only hits are the repository name in the update check and a third-party package's author e-mail in its own metadata.
- **Nothing else sensitive is published,** but two things are public by nature: the author's name and GitHub login on the commits, and the update repository name inside the app.
- **Checks:** typecheck, lint, branding and origin checks clean; vitest 207 passed (9 new tests for the GitHub update, against a fake GitHub); e2e of the updated screens passed.
